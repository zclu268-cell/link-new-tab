## 默认按需与停止后的工作量

在临时扩展副本中，于 video.js 之前包装原生 DOM 方法、观察器、事件注册与调度方法，仅计数扩展 isolated world 的调用，保留原生操作。页面自身的播放计时器和查询不计入。默认启动阶段也被计数。

相同测试副本、页面及操作，只替换 video.js 为 v1.1.2，进行一次基线采样。页面含一个视频；动态测试有 5 轮嵌套节点替换、滚动、尺寸与媒体事件。v1.1.2 默认自动跟踪，新版默认按需，因此此表比较的是默认行为变化，并非两种模式同时工作时的算法提速。

| 扩展视频操作 | 1.1.2 默认 | 1.2.0 默认 |
| --- | ---: | ---: |
| 启动：全文视频查询 | 1 | 0 |
| 启动：创建且保持活跃的观察器 | 4 | 0 |
| 启动：视频媒体监听 | 9 | 0 |
| 启动：滚动、窗口与全屏监听 | 3 | 0 |
| 5 轮动态变化：子树视频查询 | 5 | 0 |
| 5 轮动态变化：视频位置读取 | 10 | 0 |
| 5 轮动态变化：观察器回调 | 5 | 0 |
| 5 轮动态变化：定时 / 动画帧回调 | 5 / 10 | 0 / 0 |

无视频的手动请求只查询一次，未创建观察器；随后插入视频仍保持休眠。跨域测试明确检查顶层、空 iframe 和含视频 iframe 三个独立扩展 world，空框架不激活，视频框架可进入原生画中画。

手动停止、关闭自动模式、手动会话移除最后一个视频后，检查观察器、媒体监听、页面生命周期监听、布局监听、计时器和动画帧均释放。停止后继续触发页面活动，所有计数为 0；已经进入的原生画中画保持打开。异步竞态测试仅延迟真实 PiP API 返回的 Promise 完成，确认停止后旧完成回调不会重建控件。

真实设置面板页面覆盖默认开关、手动显示、停止、自动模式切换。仅临时测试副本增加 tabs 权限帮助面板识别测试标签；产品权限保持 storage 和 activeTab。面板在 380 × 600 视口下无横向溢出，显示和停止按钮均在可见范围内；检查截图存于本地测试结果。自动化未验收真实工具栏点击授予 activeTab 的过程。

默认仍会加载轻量内容脚本并读取本地设置，链接启用时仍需处理用户点击。手动启动后仍会检测当前页的视频；自动模式也会持续发现新视频。不能将“默认视频 DOM 工作量为零”等同于整个扩展绝对零开销或所有网站响应速度不变。自动模式停止本页只针对当前已加载框架，新加载 iframe 仍遵循全局自动设置。

## 链接监听与旧脚本清理

CDP 原生事件检查验证：全局关闭或排除当前网站后，真实 capture click 监听为 0；重复开启后始终只有 1 份。更改视频自动设置或前后台打开偏好，不会反复增删点击监听。真实 runtime.reload 后旧页首次点击解绑失效监听，保留原生事件和导航。

视频生命周期测试使用真实 chrome.runtime.reload() 和临时辅助扩展的 chrome.management.setEnabled(false)。上下文失效后，在后续受监听活动中清理旧按钮、全部视频监听和排队任务；再次活动的查询、布局、计时器及动画帧计数为 0。停用扩展时原生画中画保持打开。自动模式中，同一视频节点连续移除和插回 3 次，均只恢复一组 9 类媒体监听。

测试辅助扩展的 management 权限不属于产品。命令行测试环境可能在 reload 后留下停用状态；测试先记录实际状态、完成旧脚本清理断言，再明确重新启用以验证新页恢复。没有固定轮询，因此静止旧页不保证立即移除按钮。磁盘更新不能替换旧页已运行代码，升级仍需重新加载扩展并刷新网页。

## 激活后的性能回归

原有自动模式的增量发现、可见视频候选、节流定位及后台暂停全部保留验证。含 120 个视频的长列表进行 12 次实际滚动，本轮视频位置读取 25 次，屏幕外读取 4 次；无关固定尺寸内容更新不触发整页视频扫描或已有视频祖先重建。停止滚动后，无持续定位任务。

这些操作计数不能换算为真实网页加载速度、输入延迟或整浏览器流畅度的固定改善比例。测试不覆盖所有网站脚本、广告、视频解码或用户的全部扩展组合，也不能单凭这些结果确认先前整浏览器卡顿的唯一原因。可使用 README 中的命令重现；详细报告位于 test-results/，不纳入源码包。
