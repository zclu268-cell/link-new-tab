# 实现说明

扩展使用 Manifest V3，运行源码集中在 `extension/`，无需编译即可加载。测试与打包工具留在仓库根目录，不进入扩展发布 ZIP。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 声明权限、后台 service worker、弹窗和内容脚本 |
| `shared.js` | 网址校验、设置默认值与规范化、域名启用判断 |
| `background.js` | 校验内容脚本消息、读取设置、创建新标签页 |
| `content.js` | 过滤链接点击、阻止原页面导航、处理失败提示 |
| `video.js` | 发现视频、选择目标播放器、显示按钮并调用原生画中画 API |
| `popup.html` / `popup.css` / `popup.js` | 中文设置面板、当前网站识别和视频按钮定位 |
| `icons/` | 本地扩展图标 |

## 链接处理

内容脚本在 `document_start` 注册捕获阶段的点击监听，使用 `event.composedPath()` 查找链接，因此可以处理动态插入的普通链接，以及开放 Shadow DOM 中可出现在事件路径上的链接。

只有可信、可取消、未被其他逻辑取消且不带修饰键的左键点击才会被接管。下载链接、同文档锚点、特殊协议、编辑区域以及按钮和页签等操作控件被排除。网址会解析为绝对地址并限制为 HTTP / HTTPS。

处理流程：

1. 内容脚本发送 `GET_SETTINGS`，取得设置和顶层网站域名；初始化完成前保留页面原有行为。
2. 符合条件的点击发送 `OPEN_LINK`，随后取消原始跳转和后续点击处理。
3. 后台校验发送者、目标网址和最新设置，调用 `chrome.tabs.create()`，将新标签页放在来源标签页右侧。
4. 打开失败时显示可手动点击的链接和提示，避免静默丢失用户的操作。

设置更新通过 `chrome.storage.onChanged` 传播，后台在创建标签页前再次检查开关。每个框架都能处理自己的链接，是否启用则按照顶层网站判断。

由于拦截阶段早于页面的大部分点击处理，依赖自定义点击脚本的网页流程可能受到影响。网站例外是兼容性入口；不对所有网站承诺完全一致的效果。

## 视频画中画

`video.js` 使用 `document.querySelectorAll('video')` 发现 HTML5 视频。`MutationObserver` 以短延时合并页面变化，`ResizeObserver` 和滚动事件辅助更新按钮位置，布局更新通过 `requestAnimationFrame` 合并。

目标选择优先考虑当前画中画视频；否则从可见或正在播放的视频中，优先选择可见、正在播放且可见面积较大的播放器。每个文档维护自己的视频列表和按钮。

页面按钮在独立的 Shadow DOM 中渲染，用于减少网页样式干扰。这里的 Shadow DOM 仅用于扩展按钮；视频发现本身不会递归搜索网页组件的 Shadow DOM。

点击「小窗播放」直接调用 `video.requestPictureInPicture()`，中间不先等待跨脚本消息，以保留浏览器要求的用户操作状态。退出通过 `document.exitPictureInPicture()` 完成。调用前检查视频是否有画面、API 是否支持、站点是否禁用、权限策略是否允许，以及是否处于不适用的全屏状态。

扩展弹窗只帮助显示和高亮网页按钮，不代替网页上的直接点击。弹窗向各框架发送 `PIP_SHOW_CONTROLS`，框架通过 `PIP_CONTROL_RESULT` 返回带请求 ID 的结果；弹窗汇总结果，避免顶层文档没有视频时掩盖 iframe 中可用的视频。

视频功能不依赖链接新开开关，也不绕过网站的画中画限制。

## 安全与依赖边界

- 运行时没有第三方脚本、远程代码、账号、后端或遥测请求。
- 后台只处理预期消息类型，并检查消息来自本扩展的标签页内容脚本。
- 新标签页目标在内容脚本和后台两处限制为 HTTP / HTTPS。
- 持久化数据仅为链接开关、前台切换开关和排除域名列表。
- npm 依赖仅用于开发测试与打包，`node_modules/`、测试代码和测试结果不随扩展发布。

## 验证与发布

`npm run check` 执行源码校验，`npm test` 运行本地浏览器测试；覆盖链接新开、前后台切换、例外网站、修饰键、动态链接、框架、视频发现、画中画和限制提示等行为。`npm run test:youtube` 是依赖外网与真实网站状态的补充检查。

`npm run build` 根据 `extension/manifest.json` 中的版本号生成发布文件。ZIP 根目录直接包含 `manifest.json`；使用时需先解压再通过 Chrome 加载，也可用于网上应用店上传。SHA-256 校验文件用于核对发布文件是否一致。

发布前应依次执行校验、本地测试和打包；修改源码后重新加载扩展并刷新验证页面。生成 ZIP、创建 GitHub Release 和发布 Chrome 网上应用店是不同步骤，本仓库的构建命令只生成本地文件。
