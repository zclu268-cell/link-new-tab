# 实现说明

扩展使用 Manifest V3，运行源码集中在 `extension/`，无需编译即可加载。测试与打包工具留在仓库根目录，不进入扩展发布 ZIP。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 声明权限、后台 service worker、弹窗和内容脚本 |
| `shared.js` | 网址校验、设置默认值与规范化、域名启用判断 |
| `background.js` | 校验内容脚本消息、读取设置、创建新标签页 |
| `content.js` | 过滤链接点击、阻止原页面导航、处理失败提示 |
| `video.js` | 发现视频、选择目标播放器、显示按钮并调用原生画中画 API |
| `popup.html` / `popup.css` / `popup.js` | 中文设置面板、当前网站识别和视频按钮定位 |
| `icons/` | 本地扩展图标 |

## 链接处理

内容脚本在 `document_start` 读取设置，仅在初始化完成且当前网站启用链接新开时注册捕获阶段的点击监听，使用 `event.composedPath()` 查找链接，因此可以处理动态插入的普通链接，以及开放 Shadow DOM 中可出现在事件路径上的链接。

只有可信、可取消、未被其他逻辑取消且不带修饰键的左键点击才会被接管。下载链接、同文档锚点、特殊协议、编辑区域以及按钮和页签等操作控件被排除。网址会解析为绝对地址并限制为 HTTP / HTTPS。

处理流程：

1. 内容脚本发送 `GET_SETTINGS`，取得设置和顶层网站域名；初始化完成前保留页面原有行为。
2. 符合条件的点击发送 `OPEN_LINK`，随后取消原始跳转和后续点击处理。
3. 后台校验发送者、目标网址和最新设置，调用 `chrome.tabs.create()`，将新标签页放在来源标签页右侧。
4. 打开失败时显示可手动点击的链接和提示，避免静默丢失用户的操作。

全局关闭或当前网站被排除时，真正移除点击监听；重新启用仅注册一次。无关的视频设置变化不触发链接监听重绑。扩展上下文失效后，后续点击会解绑旧监听并恢复原生行为。

`shared.js` 的 `nativeLinksOn()` 内置 ChatGPT 来源例外，匹配 `chatgpt.com` 及其子域、旧域名 `chat.openai.com`，支持大小写和单个 DNS 末尾点；不按目标链接匹配，也不匹配相似后缀域名。内容脚本和后台共同使用 `enabledOn()`，即使已有设置未保存任何排除域名也会生效。顶层 ChatGPT 页面的跨域 iframe 继承此规则；不注册链接点击监听，不新增 DOM 查询或观察器。弹窗复用共享规则，显示并锁定关闭的网站开关，视频入口独立可用。

设置更新通过 `chrome.storage.onChanged` 传播，后台在创建标签页前再次检查开关。每个框架都能处理自己的链接，是否启用则按照顶层网站判断。

由于拦截阶段早于页面的大部分点击处理，依赖自定义点击脚本的网页流程可能受到影响。网站例外是兼容性入口；不对所有网站承诺完全一致的效果。

## 视频画中画

`video.js` 在 `document_idle` 加载。默认 `videoAuto: false`，启动只读取一次设置、注册扩展消息和设置监听，不创建 DOM 观察器、不查询视频、不读取布局、不绑定页面、媒体或滚动事件，也没有轮询。

收到用户的 `PIP_SHOW_CONTROLS` 后，每个框架扫描一次；仅找到视频的框架建立跟踪，空框架继续休眠。后续手动会话持续至停止检测、全部视频移除或导航离开；不保存会话状态。开启 `videoAuto` 则允许空页面保留发现观察器，以检测后续出现的视频。`PIP_HIDE_CONTROLS` 停止本页当前已加载框架的检测，直到手动显示、切换自动设置或导航；之后新加载的 iframe 仍按全局自动设置运行。关闭自动设置会清理所有当前会话，让后续新页面和框架也保持按需检测，保留已有原生画中画。

已激活会话仅在首次激活、返回前台或用户显式请求显示按钮时全量发现视频。普通 DOM 变化由 `MutationObserver` 合并约 120ms，只检查新增子树；去除重叠子树，并剔除已断开的视频。删除已知视频或其祖先时同步视频集合；无关元素的删除不触发视频祖先重建。新增子树包含已跟踪视频时也重新检查祖先，覆盖同一轮更新内的移动和重新插入。

无视频时不注册滚动、窗口尺寸和播放器属性监听。存在视频时，仅观察视频及祖先的相关属性、视频与正文的尺寸。仅在视频成员或祖先结构变化时重建布局观察集合；无关固定尺寸区域的动画不需要重新维护这些集合。滚动和布局事件合并到约 100ms 一次，并通过 `requestAnimationFrame` 对齐绘制。后台标签页暂停发现和布局工作，保留原生媒体/PiP 事件，恢复可见后同步一次。按钮位置可能有约 100ms 跟随延迟。

每个文档维护自己的视频列表、可见候选、正在播放的视频集合和按钮。`IntersectionObserver` 维护进入视口的视频候选，滚动时的目标选择只对这些候选读取布局和样式；单次遍历选出目标，不对全部视频排序。选择优先级为当前画中画视频、可见视频，再到屏幕外正在播放的视频；可见视频中优先播放状态，其次比较可见面积。可见候选仍需通过样式检查，排除 `visibility: hidden` 等不可见状态；定位按钮时还会读取所选视频的位置。显式请求显示按钮时可以扫描全部视频；没有 `IntersectionObserver` 时使用完整视频集合回退。可见候选由浏览器异步通知，暂停或恢复观察后的首轮选择会随通知更新。

页面按钮在独立的 Shadow DOM 中渲染，用于减少网页样式干扰。这里的 Shadow DOM 仅用于扩展按钮；视频发现本身不会递归搜索网页组件的 Shadow DOM。

点击「小窗播放」直接调用 `video.requestPictureInPicture()`，中间不先等待跨脚本消息，以保留浏览器要求的用户操作状态。退出通过 `document.exitPictureInPicture()` 完成。调用前检查视频是否有画面、API 是否支持、站点是否禁用、权限策略是否允许，以及是否处于不适用的全屏状态。

扩展弹窗帮助开始或停止检测、显示和高亮网页按钮，不代替网页上的直接点击。弹窗向各框架发送 `PIP_SHOW_CONTROLS`，框架通过 `PIP_CONTROL_RESULT` 返回带请求 ID 的结果；弹窗汇总结果，避免顶层文档没有视频时掩盖 iframe 中可用的视频。

视频功能不依赖链接新开开关，也不绕过网站的画中画限制。

## 视频脚本生命周期

脚本区分休眠、运行、后台暂停和永久销毁。手动停止或关闭自动设置时清理 DOM 资源，保留消息和设置入口，允许重新激活。每次会话有独立 generation；旧画中画异步请求结束不能重建已移除的按钮，也不能影响新会话。初始设置读取用 revision 防止过时结果覆盖最新设置；BFCache 恢复前重新核对自动设置。

已激活会话的视频观察器、媒体事件、滚动、焦点、可见性变化和延迟任务等入口会检查扩展上下文是否仍有效。扩展重新加载或停用后，旧脚本在首次后续受监听活动中执行永久清理：断开观察器、取消计时器和动画帧、解绑媒体与页面事件、移除按钮并释放集合引用。没有用于探测失效的定时轮询，因此无事件的静止网页不保证立即移除旧按钮。清理不会调用 `exitPictureInPicture()`，浏览器原生播放和画中画继续由浏览器管理。

视频从 DOM 移除时解绑媒体事件并移出候选与观察集合；自动模式下重新插入后可再次跟踪，手动模式在全部视频移除后休眠。后台标签页或 `pagehide.persisted` 表示进入页面往返缓存（BFCache）时仅临时暂停；`pageshow.persisted` 恢复时重新同步。普通页面离开和扩展上下文失效走永久清理，避免恢复已销毁的脚本。

上述失效清理从 1.1.2 起生效，无法改变已运行的 1.1.1 及更早脚本。首次升级必须先重新加载扩展，再刷新旧网页或重新打开标签页；后续更新的新功能也需要刷新网页以运行新代码。

## 安全与依赖边界

- 运行时没有第三方脚本、远程代码、账号、后端或遥测请求。
- 后台只处理预期消息类型，并检查消息来自本扩展的标签页内容脚本。
- 新标签页目标在内容脚本和后台两处限制为 HTTP / HTTPS。
- 持久化数据仅为链接开关、前台切换开关、视频自动显示开关和排除域名列表。
- npm 依赖仅用于开发测试与打包，`node_modules/`、测试代码和测试结果不随扩展发布。

## 验证与发布

`npm run check` 执行源码校验，`npm test` 运行本地浏览器测试；覆盖链接新开、前后台切换、例外网站、修饰键、动态链接、框架、视频发现、画中画和限制提示等行为。`npm run test:on-demand` 检查默认休眠、手动激活和停止、自动切换及异步清理；`npm run test:performance` 在自动模式下检查真实扩展的查询和布局读取次数；`npm run test:lifecycle` 检查扩展上下文失效后的清理及页面恢复。具体结果和测试范围记录在 [验证记录](VALIDATION.md)。`npm run test:youtube` 是依赖外网与真实网站状态的补充检查。

`npm run build` 根据 `extension/manifest.json` 中的版本号生成发布文件。ZIP 根目录直接包含 `manifest.json`；使用时需先解压再通过 Chrome 加载，也可用于网上应用店上传。SHA-256 校验文件用于核对发布文件是否一致。

发布前应依次执行校验、本地测试和打包；修改源码后重新加载扩展并刷新验证页面。生成 ZIP、创建 GitHub Release 和发布 Chrome 网上应用店是不同步骤，本仓库的构建命令只生成本地文件。
